# rs2-worker — RS2 on Cloudflare Workers

The TypeScript host of the RS2 HTTP API: one stateless Worker in front of
one `TenantObject` Durable Object per tenant (R2 for files, DO SQLite for
data/idempotency/logs) plus a single `RegistryObject` for the operator
table. The spec is `docs/agents/cloudflare.md`; this file is the operator's
card. Phase status: **P4b** — every service executes (`file`, `data`, spec
stores, `pipeline`, `wrapper`, `query`, `query-template`, `template`, `auth`,
`proxy`, `sms`, `log`, `catalogue`, `services`), `code:` mounts run as
Dynamic Workers with `prefix`/`httpOut`/`store` grants, streaming, and
`compile_check` at deploy, and guest (`code:`) **store adapters** back
data/file/query/sms mounts (`store.adapter: "code:<name>@<version>"` with
socket grants — the `guest-adapters/` Redis/Mongo bundles run here).
Remaining: the `transfer` API (P5).

```sh
npm ci
cp .dev.vars.example .dev.vars      # RS2_ADMIN_TOKEN for /admin/*
npm run dev                         # wrangler dev on http://127.0.0.1:8787
npm test                            # vitest (@cloudflare/vitest-pool-workers)
npm run typecheck
```

`wrangler dev` provides local R2, SQLite DOs, alarms, cron
(`curl http://127.0.0.1:8787/cdn-cgi/local/scheduled`), and the
`worker_loaders` binding (verified working locally with wrangler 4.126).

## Provision a tenant

Every tenant request routes `Host` → tenant → `TenantObject`. With the
default `RS2_DEFAULT_TENANT=main` any host maps to `main` until a tenant is
created; the admin API (spec §B.5, gated by `RS2_ADMIN_TOKEN`) creates it:

```sh
curl -X PUT -H "authorization: Bearer dev" -H "content-type: application/json" \
  http://127.0.0.1:8787/admin/tenants/main \
  --data '{"config": {"auth": {"jwtSecret": "s3cret", "userDataset": "users"}, "operatorRoles": "A",
                       "mounts": [{"path": "/files", "service": "file", "config": {"access": "open"}},
                                  {"path": "/services", "service": "services", "config": {"access": {"read": "A", "write": "A"}}},
                                  {"path": "/auth", "service": "auth", "config": {"access": "open"}}]},
           "domains": ["api.example.test"],
           "bootstrapAdmin": {"email": "admin@example.test", "password": "pw"}}'
```

`GET /admin/tenants`, `GET|DELETE /admin/tenants/<name>` (`?confirm=<name>`),
`PUT|DELETE /admin/domains/<host>`, `PUT /admin/infras`, and
`POST /admin/reload-infras` complete the surface.


## Generated inputs

- **`src/fixtures/catalogue.json`** is `config_schema::catalogue()` as the
  Rust host emits it (`cargo run -p rs2-cli -- catalogue-dump`, the same
  document as `conformance/http/fixtures/catalogue.json`). Regenerate it
  whenever `rs2-core/src/config_schema.rs` changes so the two hosts cannot
  drift.
- **`src/vendor/hash-wasm/`** is the argon2id/bcrypt/blake2b slice of
  `hash-wasm` (MIT) with its Wasm binaries extracted to importable `.wasm`
  modules: Workers forbid `WebAssembly.compile` at runtime, which is how
  the npm package loads its embedded base64. Regenerate with
  `npm run vendor:hash-wasm` after bumping the `hash-wasm` devDependency.

## Deploy

```sh
# once per account: enable R2 in the dashboard (it needs a payment method),
# then re-run `wrangler login` so the token carries the r2 scope
npx wrangler r2 bucket create rs2-files  # the RS2_FILES binding's bucket
npm run build:shim                       # regenerate the guest shim bundle
npx wrangler secret put RS2_ADMIN_TOKEN  # gates /admin/* (required for the admin API)
npm run deploy                           # wrangler deploy
```

**Workers Paid is the intended plan.** Everything deploys on Free, but its
50-subrequest-per-invocation cap sits below the advertised `outboundCalls`
budget of 64: a guest that overruns is killed by the platform (502
`contract_violation`) instead of by RS2 (503 `limit_exceeded`). Paid raises
the cap to 1 000, and RS2's own budget is the one that binds.

To hold a deployed instance to the contract, point the conformance runner at
it (`conformance/http/README.md`):

```sh
export RS2_HOST_KIND=cloudflare
export RS2_BASE_URL=https://<worker>.workers.dev
export RS2_TENANT=<the tenant RS2_DEFAULT_TENANT names>
export RS2_ADMIN_TOKEN=…
export RS2_CF_REMOTE=1
npx vitest run --exclude '**/guest-adapter.test.ts'
```

`RS2_CF_REMOTE` turns on the memory-cap case (no per-isolate heap cap in
local workerd); `guest-adapter.test.ts` is excluded because its mock Redis
and Mongo backends are `127.0.0.1` TCP servers a deployed Worker cannot
dial. Note that the Cloudflare edge rewrites a strong `ETag` to `W/"v"`
whenever it compresses a response — the version inside is unchanged, and
both hosts accept the weak form back in `If-Match`.

`wrangler.jsonc` declares everything the Worker needs: the two DO classes
(SQLite-backed), the `RS2_FILES` R2 bucket, the `LOADER` worker-loader
binding for `code:`/`template` mounts, and the minutely cron that re-arms
lost scheduler alarms. Vars (`wrangler.jsonc` `vars`, override per
environment): `RS2_DEFAULT_TENANT` (single-tenant/local mode — unset it in
multi-tenant production), `RS2_MAIN_DOMAIN` (`<sub>.<mainDomain>` tenancy),
`RS2_LOG_LEVEL`, `RS2_CATALOGUE_HOSTS` (comma allowlist for live catalogue
fetches).

Optional secrets for custom domains (`/admin/domains/<host>` — Cloudflare
for SaaS): `CF_API_TOKEN` (a token with Zone → SSL and Custom Hostnames
edit) and `CF_ZONE_ID`. With both set, `PUT /admin/domains/<host>` also
provisions the custom hostname and the response carries the provisioning
status + DNS instructions (`RS2_CNAME_TARGET` or `RS2_MAIN_DOMAIN` is the
CNAME target it reports); without them the endpoints manage the registry
map only.

## Limits and differences from the Rust host

All declared in the spec (`docs/agents/cloudflare.md` §A) and observable in
`GET /.well-known/rs2/services` → `limits` (`host: "cloudflare"`):

- Wasm `code:` bundles → **501** `engine_unavailable`; JS only (`engines: ["js"]`).
- Guest `ctx.request`/`ctx.state`/`ctx.readBody` are **async** (the
  `guest-async` facet); timers are real, platform globals are not shadowed.
- Memory is the platform's fixed 128 MiB per isolate; materialized-body cap
  is 32 MiB (vs 100 MiB); guest budgets are CPU-time (`limits.cpuMs`, default
  5 000, ceiling 30 000) reported as `wall_clock_ms` breaches.
- Opaque validators (ETags, config version) are different strings; clients
  round-trip them.
- `conditional-write` is atomic here (DO-serialized); absent-directory
  DELETE is 204 (R2 has no directories); platform-canonicalized dot
  segments route on the normalized path.
- Guest (`code:`) store adapters run one Dynamic Worker isolate per mount:
  `store.maxRuntimes`/`store.idleMs`/`store.idleSeconds` are accepted and
  **ignored** (the platform owns eviction), and backend connections cannot
  pool across requests (I/O objects are request-scoped) — portable
  adapters reconnect per invocation; the shipped `guest-adapters/` bundles
  do. The 501 `engine_unavailable` remains only when the deployment has no
  `worker_loaders` binding. `builtin:mem` is durable (DO SQLite), not
  ephemeral.

## Conformance

The black-box runner lives in `conformance/http/`:

```sh
cd conformance/http
RS2_PORT=8787 RS2_ADMIN_TOKEN=dev npm run host:cf       # terminal 1
RS2_HOST_KIND=cloudflare RS2_PORT=8787 RS2_ADMIN_TOKEN=dev npm test   # terminal 2
```

The memory-cap code test is skipped on local `wrangler dev` — local workerd
enforces no per-isolate heap cap — unless `RS2_CF_REMOTE` is set (run against
a deployed Worker to exercise it).
